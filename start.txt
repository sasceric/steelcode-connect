Symfony Messenger kao srce sistema

Messenger bi bio jedan od najvažnijih dijelova.

Na primjer:

final readonly class StartCatalogSync
{
    public function __construct(
        public string $tenantId,
        public string $connectionId,
    ) {
    }
}

Handler:

#[AsMessageHandler]
final readonly class StartCatalogSyncHandler
{
    public function __construct(
        private DistributorRegistry $distributors,
        private MessageBusInterface $bus,
    ) {
    }

    public function __invoke(StartCatalogSync $message): void
    {
        $adapter = $this->distributors->forConnection(
            $message->connectionId
        );

        foreach ($adapter->fetchProductPages() as $page) {
            $this->bus->dispatch(
                new ImportProductPage(
                    tenantId: $message->tenantId,
                    connectionId: $message->connectionId,
                    page: $page,
                )
            );
        }
    }
}

Transporti:

framework:
    messenger:
        transports:
            async_catalog: '%env(MESSENGER_CATALOG_DSN)%'
            async_stock: '%env(MESSENGER_STOCK_DSN)%'
            async_media: '%env(MESSENGER_MEDIA_DSN)%'
            failed: 'doctrine://default?queue_name=failed'

Routing:

framework:
    messenger:
        routing:
            App\Sync\Message\ImportProductPage: async_catalog
            App\Sync\Message\UpdateStockBatch: async_stock
            App\Sync\Message\DownloadMedia: async_media

Tako možeš nezavisno skalirati stock, katalog i slike.

Adapteri

Symfony dependency injection je odličan za registry konektora.

interface DistributorAdapterInterface
{
    public function supports(string $provider): bool;

    public function testConnection(
        DistributorConnection $connection
    ): ConnectionTestResult;

    public function fetchProducts(
        DistributorConnection $connection,
        ProductCursor $cursor
    ): ProductPage;
}

KimTec:

final readonly class KimTecAdapter implements DistributorAdapterInterface
{
    public function supports(string $provider): bool
    {
        return $provider === 'kimtec';
    }
}

Registry:

final readonly class DistributorRegistry
{
    public function __construct(
        #[TaggedIterator('app.distributor_adapter')]
        private iterable $adapters,
    ) {
    }

    public function get(string $provider): DistributorAdapterInterface
    {
        foreach ($this->adapters as $adapter) {
            if ($adapter->supports($provider)) {
                return $adapter;
            }
        }

        throw new UnsupportedDistributorException($provider);
    }
}

Service config:

services:
    _instanceof:
        App\Integration\DistributorAdapterInterface:
            tags: ['app.distributor_adapter']

Ovo je veoma čisto i lako proširivo.

I onda Connect postaje prava commerce integration platforma, ne samo distributor importer.

Gdje je Shopware u toj priči?

Shopware više nije glavni sistem kroz koji sve mora prolaziti. On je samo jedan od kanala:

SteelCode Connect = centralna integracijska logika
Shopware = webshop i order management
OLX = marketplace kanal
Ananas = marketplace kanal
KimTec = supplier
Pantheon = ERP/računovodstvo

To je važno jer neki korisnik možda želi:

KimTec → OLX

bez Shopwarea.

Drugi želi:

Pantheon → Shopware + OLX + Ananas

Treći:

Shopware → OLX

Sve kombinacije koristi isti sistem.
