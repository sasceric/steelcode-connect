# SteelCode Connect

SteelCode Connect is a multi-tenant commerce integration hub. It provides a central product catalog that imports supplier data and publishes it to sales channels such as Shopware and OLX.

The product architecture and MVP scope are described in [the technical specification](docs/steelcode-connect-technical-specification.md). For the current delivered scope and prioritized remaining work, see the [implementation status](docs/implementation-status.md).

For step-by-step purchasing, warehouse, customer, order and Shopware synchronization workflows, read the [Inventory and Sales operating guide](docs/inventory-and-sales-guide.md). It explains stock effects, setup/cutover, daily operations, exceptions and current release boundaries.

## Stack

- Frontend: Nuxt 4, Vue 3, TypeScript, Nuxt UI, Tailwind CSS and Pinia
- Frontend base: [Nuxt UI Dashboard template](https://github.com/nuxt-ui-templates/dashboard)
- Backend: Symfony 7.4, Doctrine ORM, Twig, Dompdf, Messenger and Scheduler
- Database: PostgreSQL 18
- Mail: Brevo SMTP

## Features implemented

- Session-based sign-up, login, logout, password reset and password change
- Bosnian as the primary locale, with English and German available per user
- Tenant/company details, reusable addresses and payment methods
- Pricing plans, monthly and annual subscriptions, and billing history
- PDF invoices generated by Symfony from backend/templates/documents/invoice.html.twig
- Annual subscriptions are invoiced upfront; renewals are due on the same date each following year
- Branded password-recovery email templates in backend/templates/email/
- Central catalogue with parent products and child variants, product option groups and translations
- Product editor with a persistent save action, HTML/WYSIWYG description editor, fulfilment, dimensions, visibility and product extensions
- Regular product pricing stored on the product: currency, tax rate, selling, purchase and list price (gross/net)
- Shopware-style advanced-pricing editor: quantity tiers, gross/net price linking, list price and 30-day lowest price
- Categories, manufacturers, properties, custom fields, taxes, units, delivery times, stock foundations and media gallery management
- Shared currencies and locale catalogues; Bosnian, English and German are available in the application
- Tenant integration records for Shopware, WooCommerce, OLX and Ananas, with encrypted credentials and connection testing
- Queued Shopware catalogue imports with persisted phase progress, per-run logs, polling UI and a Doctrine Messenger failure queue

## Catalogue and pricing

The canonical catalogue is intentionally independent from any one sales channel. Shopware variants and WooCommerce variations are stored as child products using `parent_id`; systems without variants receive separate products during export.

The product detail page follows the Shopware-style structure:

- **General**: core product data, rich HTML description, regular prices, delivery, labelling and visibility.
- **Variants**: option groups and generated child products.
- **Gallery**: upload, securely serve, reorder, replace and delete product images; the first image is the cover. `product_media` stores file name, extension, size, MIME type, checksum and position, while files remain outside the public web root.
- **Advanced pricing**: each pricing rule has quantity tiers. A tier contains the three price types—price, list price and lowest price in the previous 30 days—with gross/net inputs linked independently.
- **Extensions**: connector-specific fields such as Shopware custom fields and WooCommerce meta data.
- **Relations**: downloadable product documents and Shopware cross-selling groups with assigned products.

SEO URLs use the reusable `seo_urls` table rather than copied columns on product, category or manufacturer translations. A canonical URL belongs to a tenant, entity type, entity ID and locale, with an optional sales-channel scope for future channel-specific routes. Changing it retains the previous path as a 301 redirect. The current catalogue UI edits the global URL for the selected locale.

Regular prices are persisted directly on `products`. Advanced price rows use `product_prices` so Shopware quantity tiers and rule contexts can be retained without duplicating the regular price.

## Local setup

### 1. PostgreSQL on macOS

Install and start PostgreSQL:

    brew install postgresql@18
    brew services start postgresql@18

Stop it when it is not needed:

    brew services stop postgresql@18

Add the PostgreSQL binaries to zsh once:

    echo 'export PATH="$(brew --prefix postgresql@18)/bin:$PATH"' >> ~/.zshrc
    source ~/.zshrc

Create the local role and database:

    psql postgres

    CREATE ROLE root WITH LOGIN PASSWORD 'Root1234$';
    CREATE DATABASE steelcode_connect OWNER root;

If the role already exists:

    ALTER ROLE root WITH LOGIN PASSWORD 'Root1234$';

Exit psql with \q.

root / Root1234$ is strictly local-development configuration. Do not use it outside your machine or commit it.

### 2. Backend

Create backend/.env.local with local configuration:

    DATABASE_URL="postgresql://root:Root1234$@127.0.0.1:5432/steelcode_connect?serverVersion=18&charset=utf8"
    FRONTEND_URL="http://localhost:3000"

    INVOICE_ISSUER_NAME="Your company name"
    INVOICE_ISSUER_OIB="Your Company ID"
    INVOICE_ISSUER_PDV="Your VAT ID"
    INVOICE_ISSUER_ADDRESS="Street, ZIP City, Bosnia and Herzegovina"
    INVOICE_ISSUER_EMAIL="billing@example.com"
    INVOICE_ISSUER_PHONE="+387 ..."

    BREVO_SMTP_HOST="smtp-relay.brevo.com"
    BREVO_SMTP_PORT=587
    BREVO_SMTP_USERNAME="your-brevo-smtp-username"
    BREVO_SMTP_KEY="your-brevo-smtp-key"
    BREVO_FROM="info@example.com"

Install dependencies, create the schema and run the API:

    cd backend
    composer install
    php bin/console doctrine:database:create --if-not-exists
    php bin/console doctrine:migrations:migrate
    php -S 127.0.0.1:8000 -t public

The API runs at http://127.0.0.1:8000.

Run the background import worker in a separate terminal whenever you import catalogue data:

    cd backend
    composer imports:consume

The worker also runs the scheduler for incremental Shopware Sales synchronization and stock-outbox dispatch. Read the [Shopware Sales and inventory cutover guide](docs/shopware-sales-inventory-cutover.md) before enabling ongoing order sync or Connect-owned stock.

The import worker intentionally runs with Symfony debug and Doctrine query profiling disabled. A large catalogue produces thousands of queries; keeping the dev profiler active retains those queries in memory and can terminate the worker. The import screen queues one Shopware catalogue run and shows its current phase while this worker is running. An active or queued run can be cancelled from either the import page or its persistent progress card; work stops after the current item and already imported records are retained. The dependency order is sales channels, currencies, units, tags, taxes, delivery times, manufacturers, property groups and values, custom-field definitions and categories; products, variants, prices, media assignments and translations follow, then canonical Shopware SEO URLs and product downloads/cross-selling. The Shopware integration needs read permission for `seo_url`, `language`, `locale`, `sales_channel`, `product-download` and `product-cross-selling` to import the complete catalogue.

Each run has a viewable diagnostic log in the integration configuration page. Log entries are also written to `backend/var/log/integrations/shopware-YYYY-MM-DD.log`; credentials and complete source payloads are never logged. Failed jobs are retained in the `failed` Messenger queue for inspection and retry.

### 3. Frontend

In a second terminal:

    cd frontend
    nvm use 22
    corepack enable
    corepack pnpm install
    corepack pnpm dev

Open http://localhost:3000.

The Nuxt development server proxies /api to the Symfony API. The browser only receives the HTTP-only session cookie; protected routes restore the session through /api/v1/auth/me.

## First account

1. Start PostgreSQL, Symfony and Nuxt.
2. Open http://localhost:3000.
3. Select Sign up and enter the company name, email and password.
4. The account is created as the tenant owner.

## Billing and invoices

Company owners select plans in Company → Pricing plans:

| Plan | Monthly | Product limit | Annual upfront price |
| --- | ---: | ---: | ---: |
| Starter | 100 KM | 1,000 | 1,080 KM |
| Growth | 200 KM | 5,000 | 2,160 KM |
| Enterprise | 300 KM | Unlimited | 3,240 KM |

Annual billing applies a 10% discount and creates the first invoice immediately. Annual renewals are generated on the subscription anniversary. Monthly invoices are generated on the first day of each month.

Run the universal invoice generator manually:

    cd backend
    php bin/console app:invoices:generate

For testing or restoring a specific billing period:

    php bin/console app:invoices:generate --date=2026-07-01

The old app:invoices:generate-monthly command remains as an alias.

For production, keep Symfony Scheduler running:

    cd backend
    php bin/console messenger:consume scheduler_default -vv
    or to simulate production, run the scheduler:
    composer import:consume
Invoices are uniquely constrained by tenant and billing period. They use the per-year format YEAR-001, YEAR-002, and reset to 001 each year. Invoice customer information comes from Company Details and the tenant’s default address. PDF rendering uses the black-and-white logo at backend/public/media/sc-connect-logo.svg.
